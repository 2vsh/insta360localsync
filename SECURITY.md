# Security and privacy

Insta360 Local Sync is a local, single-user download and media tool. The control page binds to `127.0.0.1`, validates the HTTP Host header, rejects cross-site browser requests, and requires a per-process token for changes. Derived thumbnails, previews, and exports require that token too; their URLs can reveal it, so keep those URLs private. Media routes resolve only completed manifest entries and fixed cache assets, reject originals changed since backup, and check real paths against the destination to prevent symbolic-link escapes. They support byte ranges for seeking and do not expose arbitrary filesystem paths or original-file downloads. The app does not provide user accounts or authentication between people sharing the same Windows session. Keep it on loopback; exposing it through a reverse proxy or public tunnel is outside the supported access model.

The app has no analytics, telemetry, cloud upload, or npm dependencies. It contacts the camera address you configure. Opening documentation links in a browser is separate from downloading footage. Camera file URLs must use that same origin, redirects are not followed, and HTTPS certificate validation is left enabled. Downloaded files are stored as bytes, not executed.

The Windows downloader only lists and retrieves camera files. It never deletes camera originals. The older Raspberry Pi proposal in `insta360-self-hosted.md` is separate reference material and includes an optional deletion setting; it is not run by the Windows app.

Media processing invokes locally installed FFmpeg/FFprobe directly without a shell, uses fixed filter graphs and validated numerical camera paths, restricts input protocols to local files/pipes, and queues expensive jobs. Keep those executables current. Derived footage, render instructions, and exports live in the ignored `.local/media/` cache; director drafts also live in browser local storage. These can contain private images and recording information even after the camera is disconnected. Browser downloads use the location selected by the user or the browser's download settings. Cache cleanup and its effect on exports are described in the README.

Local settings and backup metadata may contain destination paths, camera serial numbers, filenames, and machine details. Logs and screenshots can reveal those too. They belong on the collecting PC, not in a public issue or commit. Keep custom configuration under `.local/` and run `npm run check:public` before publishing. The check does not audit older Git history or replace a manual review.

For a security concern, use the repository's private vulnerability-reporting option if the maintainer has enabled it. Otherwise, open an issue asking for a private contact without posting credentials, footage, serial numbers, personal paths, or exploit details. Use synthetic fixtures when reporting bugs.
